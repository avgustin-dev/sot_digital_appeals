Для бэкенда. Что изменил фронт (правка 19.08.2026)
==================================================
Репозиторий фронта: sot-priem-front, ветка main.
Пути API не менялись. Префикс /api/v1, camelCase, JWT.

Ниже — что реально поменялось на фронте и что из-за этого нужно
на бэке. Что не трогать — в конце.


1. Папки content/ на фронте больше нет
--------------------------------------
Фронт больше не везёт site.json, eligibility-tree.json, survey.json,
booking-rules.json, dictionaries.json.

Тексты сайта, ФИО руководства, правила, дерево допуска — только из API:

  GET /public/bootstrap
  PUT /staff/content
  PUT /staff/eligibility
  GET/PUT /staff/calendar

Кнопки интерфейса (ru/ky) живут на фронте в src/locales/. Это не CMS.

Если бэк при старте сам кладёт сид из старого content/ — гражданин
увидит эти тексты, пока админ не сохранит свои.
Это нормально, пока сид нужен. Если проверяете «пустой сайт» —
сид контента на бэке лучше выключить или дать пустые site / tree.

Кнопка «Очистить» в админке сайта шлёт PUT /staff/content
с пустыми строками и пустыми массивами (leadership=[], headerNav=[],
rules.rulesRu=[] и т.д.). Нужно принять такой JSON и отдать его
обратно в bootstrap без подстановки шаблона.


2. Личный график руководства — dayWindows (как раньше просили)
--------------------------------------------------------------
В PUT /staff/content у лица:

  windowKind: "fixed" | "calendar"
  dayWindows: [ { weekday, startMinutes, endMinutes } ]
  weekdays, startMinutes, endMinutes — старые поля, для совместимости

weekday: 0=вс … 6=сб (как Date.getDay()).
Минуты от полуночи: 09:00 = 540, 15:00 = 900.

Нужно:
- не выкидывать dayWindows в bootstrap и PUT content;
- GET /public/slots и GET /public/dates для windowKind=fixed:
  окно того дня недели, на который запрошена дата.
  Вторник 15:00–16:00 и четверг 09:00–12:00 — разные слоты.
  Нельзя резать все дни одним startMinutes/endMinutes с карточки.
- windowKind=calendar — только календарь платформы
  (receptionWeekdays, dayStartMinutes, dayEndMinutes).

Сейчас TargetWindowResolver на бэке берёт одно окно на все дни.
Это надо поправить, иначе CMS врёт гражданину.


3. Оценка сервиса /service-evaluation/{code}
--------------------------------------------
Фронт больше не уводит гражданина с талона принудительно.
После приёма он может смотреть запись и перейти на оценку по ссылке.

Страница оценки вызывает без PIN:

  GET /public/appointments/{code}

В ответе нужны appointment, appealStage, feedback (если уже есть).
PIN для оценки не требовать.

Отправка / правка оценки:

  POST /public/appointments/{code}/feedback
  { respectful, clearNextSteps, convenient, deadlinesMet, comment? }

Если оценка уже есть — обновить, не 409.
Не принимать, только если запись/обращение cancelled.

После completeReception (status completed) в письме/SMS лучше дать:

  {публичный_origin}/service-evaluation/{code}

без PIN. Сейчас NotificationService пишет только в лог —
письма до гражданина не доходят.


4. «Моя запись»: unlock + lookup
--------------------------------
После кода и PIN фронт делает:

  POST /public/appointments/{code}/unlock   { pin }
  GET  /public/appointments/{code}

Unlock — запись.
Lookup — этап обращения, оценка, последнее уведомление.

Lookup не отдаёт assignment / protocol / controlLog —
так и задумано, кабинет их берёт из GET /staff/appeals.


5. Опросник отложен
-------------------
Публичный /survey и кабинет /admin/survey — заглушка «В разработке».
Фронт опросник больше не заполняет и не редактирует.

GET/PUT /public/survey и /staff/survey можно не трогать и не ломать.
Просто ими пока никто не пользуется.


6. Дерево допуска
-----------------
Если GET bootstrap / eligibility отдаёт пустой массив,
запись на приём на фронте блокируется («дерево не заполнено»).
Это ожидаемо, пока админ не сохранит дерево.

PUT /staff/eligibility с пустым nodes[] — допустимо (кнопка очистки).


7. Слоты при ошибке
-------------------
Если GET /public/dates или /public/slots падает (5xx, сеть),
фронт показывает «сервис недоступен», а не «нет дат».
Пустой список дат при 200 — это по-прежнему «нет слотов».


Что на бэке делать не нужно
---------------------------
- PDF отчёта: печать на фронте, эндпоинт не нужен.
- QR талона: рисует фронт, в QR только
  {origin}/appointment-status?code={CODE}  (PIN нет).
- Коды статусов поручения: open | in_progress | done | overdue.
  В письмах лучше русские/кыргызские слова, не Open.
- CRUD сотрудников, смена пароля, вложения — вне этой правки.
- Пути и тела запросов кабинета (confirm, reject, reception,
  prep, control, calendar) — без изменений.
