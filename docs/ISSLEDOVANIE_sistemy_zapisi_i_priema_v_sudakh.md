ИССЛЕДОВАНИЕ
Системы записи, приёма граждан и цифровых сервисов судов
(высшие и связанные суды, а также релевантные судебные практики)

Документ для копирования в Google Docs / текстовый редактор
Дата подготовки: август 2026
Назначение: сбор ссылок и фактических данных по юрисдикциям, у которых есть элементы, пригодные для изучения и заимствования при проектировании цифровой платформы приёма / записи граждан.


────────────────────────────────────────
1. ЦЕЛЬ И ПОДХОД
────────────────────────────────────────

Цель документа — не выбрать «лучшую» систему и не собрать «лучшее по частям» в готовый гибрид, а зафиксировать:

• где в мире уже существуют работающие сервисы, близкие к приёму граждан, записи на приём, посещению суда, электронным обращениям и связанным цифровым каналам;
• какие именно функции и данные доступны публично;
• у каких систем есть что взять (отдельные практики, модели, интерфейсные решения, регламенты), даже если система в целом решает другую задачу (не личный приём председателя, а, например, запись к клерку, туры, e-filing, электронные обращения).

В документ включены только юрисдикции и сервисы, у которых есть наблюдаемый, описанный или доступный онлайн элемент, который можно изучать. Системы «только контакты и телефон без сервиса» в основной перечень не включены, если нет отдельного полезного слоя (регламент, график приёма, электронная подача и т.п.).


────────────────────────────────────────
2. ТИПЫ СЕРВИСОВ, КОТОРЫЕ РАССМАТРИВАЛИСЬ
────────────────────────────────────────

Для удобства чтения в разделах ниже используется условная типология. Это не рейтинг, а классификация найденного.

Тип A. Личный / онлайн-приём руководства суда (председатель, заместители, приёмная)
Тип B. Онлайн-запись к аппарату / клерку / канцелярии (слоты, календарь, типы услуг)
Тип C. Посещение суда, туры, галерея, visitor pass / e-pass
Тип D. Электронная подача документов, e-filing, судебный кабинет
Тип E. Портал обращений / электронная приёмная / статус обращений
Тип F. Интеграция с гос-ID / единым окном госуслуг
Тип G. Регламент и публичный график приёма (даже без онлайн-записи)

У одной юрисдикции может сочетаться несколько типов.

3.1. Республика Казахстан — Верховный Суд и судебная система
────────────────────────────────────────

Типы: A, D, E, F (и близкие к B через электронные сервисы)

Официальные и сервисные ссылки:
• Официальный сайт Верховного Суда РК: https://sud.gov.kz/rus
• Электронная запись на приём (страница ВС РК): https://sud.gov.kz/rus/electronic-appointment
• Судебный кабинет (единое окно электронных сервисов судов): https://office.sud.kz/
• Единый портал судебных органов: https://portal-sot.kz/
• Страница ВС на gov.kz: https://www.gov.kz/memleket/entities/sud
• Платформа электронных обращений eOtinish (гос-уровень, в т.ч. обращения в органы): https://eotinish.kz/  (также через eGov: https://egov.kz/ )
• Материалы о eOtinish: https://egov.kz/cms/en/news/eOtinish_platform

Что есть по факту (по открытым описаниям):
• На сайте ВС РК прямо заявлена услуга «Электронная запись» на приём для граждан и представителей юридических лиц; услуга бесплатна; есть правила записи.
• «Судебный кабинет» (office.sud.kz) — единое окно электронных сервисов судебной системы: авторизация (в т.ч. через eGov / ЭЦП), мобильные приложения, набор судебных e-услуг.
• eOtinish — межведомственная платформа электронных обращений: подача, отслеживание статуса, история взаимодействий, оценка; запущена с 2022 г.; по открытым сообщениям — миллионы обращений на уровне всей госсистемы (не только суд).
• Председатель ВС по закону / практике может лично принимать граждан и организации (канал прямого доступа к руководству суда — публично упоминается в описаниях роли председателя).

Что можно взять (как объект изучения, без оценки «лучше/хуже»):
• Модель онлайн-записи именно на приём (а не только на туры или к клерку).
• Связка: официальный сайт суда + отдельный «судебный кабинет» + гос-ID.
• Правила записи, вынесенные публично рядом с формой.
• Опыт единой электронной приёмной / обращений (eOtinish) для статуса и истории.
• Единый портал судебных органов как «одна точка входа» в экосистему.

• Госуслуги — подача в суды: https://www.gosuslugi.ru/600443/1/form

Что есть по факту:
• Приём документов в приёмной ВС РФ — по открытым данным, без предварительной записи, в порядке очереди, с документом, удостоверяющим личность; указаны часы работы.
• Отдельные каналы: процессуальные обращения, электронное правосудие, экономический контур (Мой арбитр).
• ГАС «Правосудие»: личный кабинет через ЕСИА / УКЭП; подача обращений; отслеживание движения; электронная приёмная судов общей юрисдикции.
• На уровне многих судов общей юрисдикции — регламенты личного приёма председателя (категории обращений, не связанные с конкретным делом / обжалованием судебных актов).

Что можно взять:
• Чёткое разделение каналов: процессуальные документы / внепроцессуальные обращения / личный приём.
• Модель электронной приёмной с авторизацией через гос-ID.
• Публичный регламент, что можно и нельзя поднимать на личном приёме.
• Опыт «личного кабинета» + статусы обращений.

Ссылки — примеры онлайн-записи к клерку (не SCOTUS, но судебная практика США):
• Los Angeles Superior Court — Online Clerk’s Office Appointment Scheduler: https://mycourtservices.lacourt.org/Appointment/Schedule

Что есть по факту:
• SCOTUS: здание открыто для посетителей (часы, правила, образовательные программы); Clerk’s Office — отдельные телефоны; e-filing для представленных адвокатами сторон (бумажный контур остаётся официальным; pro se — бумага).
• Штатные суды (пример LA / Riverside): онлайн-календарь записи к клерку / self-help / collections; выбор courthouse → тип appointment → слот; цель — снизить очереди и телефонные записи.
• Типы услуг клерка явно ограничены: информация о правилах/процедурах, без юридических консультаций по существу дела.

Что можно взять:
• UX пошаговой записи: локация → тип услуги → слот.
• Разграничение «что клерк/аппарат может / не может» (публичные правила).
• Visitor guidelines и отдельный канал «визит vs деловая услуга».
• Практика e-filing + публикация материалов на docket (у SCOTUS — для электронных подач).

6. ЗАМЕЧАНИЯ ПО ГРАНИЦАМ СРАВНЕНИЯ
────────────────────────────────────────

1) «Запись на приём к председателю» как отдельный массовый онлайн-продукт встречается редко. Ближе всего к этому контуру — Казахстан (электронная запись на приём) и постсоветские регламенты личного приёма (РФ, РБ, Татарстан) с разной степенью цифровизации.

2) В странах common law (UK, US SCOTUS, Canada, Singapore) сильнее развиты:
• визиты/туры/слушания;
• clerk services и e-filing;
а не «личный приём главы суда по обращениям граждан» в стиле административной приёмной.

3) E-filing и «запись на приём» — разные продукты. Их можно стыковать в одной экосистеме (пример: Сингапур — eLitigation + Service Bureau appointment; Казахстан — Судебный кабинет + electronic-appointment), но это не одно и то же.

4) Гос-ID (eGov, ЕСИА, Singpass, e-ID) почти всегда является опорной точкой зрелых электронных судебных сервисов.

5) Все ссылки и описания — по состоянию на открытые источники на момент подготовки документа (2026). Интерфейсы и URL могут меняться; перед digests/презентацией имеет смысл перепроверить ключевые страницы.

8. ЗАКЛЮЧЕНИЕ (без выбора «победителя»)
────────────────────────────────────────

По открытым данным, для задачи «цифровая платформа приёма / записи граждан при верховном (или аналогичном) суде» наиболее прямой объект изучения по записи на приём — контур Казахстана (electronic-appointment + судебный кабинет + e-обращения).

Параллельно имеет смысл опираться на набор функций из разных систем — не как на «сборку лучшего», а как на каталог работоспособных практик:

• регламент и границы приёма — РФ / РБ / Татарстан;
• электронная очередь через госуслуги — Татарстан;
• appointment к аппарату/бюро — США (штаты), Сингапур (Service Bureau);
• visitor / tour / e-pass — Индия, UK, Canada, SCOTUS;
• e-filing и статусы — Сингапур, Эстония, ГАС «Правосудие», eCourt PH, office.sud.kz;
• единый ID и единое окно — eGov/eOtinish, ЕСИА, Singpass, Public e-File.

Следующий логичный шаг после этого документа (по отдельному запросу): не «выбрать лучшее», а на базе инвентаря функций сопоставить, какие блоки уже есть в текущей демо-платформе КР и какие пробелы закрыть ссылками на конкретные зарубежные реализации.
